## 科学审查

- BioSample 连接是精确的一对一匹配，涉及 93 个样本。智能体通过无依赖的 XLSX 读取器从不可用的 Excel 包中恢复，并生成了可复现的中间表格。
- 所请求的排名无效。该分析对表 S12 的 1,077 个冗余参考序列分布进行了 CLR 变换，然后才移除非代表性序列。官方工作流是将表 S3 中的读数与最终的 957-MAG 非冗余目录重新比对；在比对后过滤竞争性参考序列并不等效。
- 在表 S3 上进行的独立未改变模型重新计算仅保留了冻结的前 10 名中的 2 个。一个冻结的领先项从显著的正硅酸盐关联变为 beta 约 -0.03 和全局 q 约 0.94。
- 稀有 MAG 过滤实际上无效，发生在 CLR 之后，并且使用的是丰度大于零而非预设的检测规则。LORO 稳定性意味着点估计保持一个符号，而非特定折叠的不确定性排除了零。
- 单独的相关营养盐回归并未确立特定营养盐的归因。缺失的最终响应也意味着没有因果警示、替代解释综合或硝酸盐-磷酸盐验证实验到达用户手中。

## 通用测试框架发现

1. 先前的一次 `ECONNRESET` 增加了共享重试计数器，并静默消耗了唯一一次无副作用的空闲重放。瞬时重试和空闲重放需要独立的状态。
2. 每次 Bash 调用都同步引导 Python 和 R。R 启动器已在随机暂存前缀下解决并重命名，导致 macOS dylib 路径指向已删除的目录。每次 shell 调用都检测到损坏的 R 环境，重建它，然后再次破坏它。十六次 P11 Bash 调用各自创建了一次回滚；隔离的配置文件累积了 133 个回滚副本。
3. 四次并行 shell 启动在全局生成授权租约内的环境修复后等待并超时。安全租约应保留，但环境发现/配置必须在其获取之前完成。
4. 通用的五分钟原始正文不活动截止时间既不是语义进度截止时间，也没有诊断价值。该路由产生了已解码的进度，然后在更长的可见间隙后失败。不活动限制应明确/按路由配置，而非任意的默认值。
5. 运行器仅将最终的助手文本和明确的结果视为可用。它保留了 23 个文件的路径/大小元数据，但未复制任何脚本、JSON 审计或分析表格，因此一次迟到的提供程序故障使 52 分钟的已完成工作看起来是空的。
6. 子任务返回了有用的源/连接备忘录，但根任务重复了大部分采集工作。这是一个效率观察，而非新的委派配额或控制器工作流的理由。

## 重新运行前的一般性修正

- 将瞬时重试计数与唯一一次空闲重放分开。
- 在持久的最终前缀下解决 Conda 环境，按语言缓存就绪状态，绝不让 Python 执行验证或修复 R。
- 在全局进程生成授权租约之前解析托管环境，同时在生成前立即重新验证授权。
- 默认禁用通用的提供程序不活动截止时间；保留调用方取消和明确的路由/总限制。
- 在每次终端运行时冻结会话拥有的代码和输出的有界、哈希快照。将其与持久结果和继承的读取授权区分开；在可恢复输出后将错误分类为部分错误。
- 即使底层读取器拒绝其取消承诺，也要解决 SDK SSE 取消问题。
